Spider Honeypots against LLM-Driven Scrapers

Redesigning traps for web scrapers that can reason.

Summary

Spider honeypots are links that only a robot would follow. They assume the robot is mechanical. A scraper driven by a large language model (LLM) can read what a page means and browse like a person, so I asked whether honeypots can be redesigned to detect LLM-driven scrapers, and what the designs need to remain undetected by them.

I built a fictional company website that logs every request, and switched on three honeypots one at a time, plus a control condition with none. Seven agents then visited it, 240 runs in all.

What this means

  • Honeypots with plausible, goal-relevant lures caught every LLM-driven agent that was asked to look for sensitive content.
  • A robots.txt rule only protects against clients that read it. Both Claude agents entered the disallowed 14-page chain in 10 of 10 runs without having requested the file.
  • Neither Claude agent followed the instruction hidden in the prompt-injection trap (0 of 10). The token was only quoted.
  • The visible link that attracts agents also caused the human baseline's one false positive.

Detection was at the ceiling, so the designs could not be ranked against each other, and no classical hidden-link honeypot was tested. The designs work in this testbed. Whether they beat classical honeypots, or resist agents built to avoid them, is still open.

Time to detection

Median seconds from the first request in a run to the first trap hit. Range in brackets. Only runs with a hit are included.

Playwright is a scripted crawler and is fast by design. The language-model agents take longer because the model processes each page (Crawl4AI) or decides each step (Claude). The extra second for the crawler that obeys robots.txt is its separate robots.txt request before the browser starts; measured from its own first page request, both crawlers take about 0.5 s. Timings depend on the machine used and are comparisons within this testbed, not general speeds.

Statistical comparisons

Eight two-sided Fisher exact tests. Each row compares how often two groups of runs hit a trap. The Bonferroni column multiplies each p-value by 8, to allow for running eight tests. A very small p means the gap between the groups is very unlikely to be chance.

Detection was at the ceiling for most agents, so these tests show a large gap from the human baseline rather than differences between the LLM agents. The two Claude agents are identical on this measure (15 of 15 each).

The three honeypots and what happened

Semantic trap

A page that looks like an internal quarterly financial export, linked from a blog post.

Successful, with a qualification

All 30 Claude and Crawl4AI runs requested it. Some replies said it looked artificial.

Prompt-injection trap

Vendor notes asking automated assistants to repeat a canary token, in a hidden comment and in small visible text.

Unsuccessful

No Claude run followed the instruction (0 of 10). The token was only quoted.

Link-graph chain

14 "restricted archive" pages, each teasing the next, disallowed in robots.txt.

Successful for behaviour, not for reasoning

Claude went deep but had not read robots.txt. 4 of 5 text-browser runs jumped to page 14 by typing an address.

Design lessons

  • Visible, goal-relevant lures attract agents that follow links.
  • Keep tell-tale labels and token names out of trap content.
  • Do not reveal a chain's length: "page 1 of 14" lets agents jump to the end.
  • A disallow entry reaches only clients that read it.

Method

  1. Design science research. Build an artifact, then evaluate it against stated criteria (Hevner et al.).
  2. Testbed. A fictional company website that logs every request and page event.
  3. Three honeypots, switched on one at a time, plus a control condition with none.
  4. Seven agents. Two mechanical crawlers; Crawl4AI with a small local model (two input modes); Claude Sonnet 5.5 (screenshots, page text); a scripted human baseline.
  5. 240 runs (60 per condition; 5 to 10 per agent and condition). Measures: detection rate, false positives, time to detection and trap depth. Exact statistics and hand-coded replies.
Agents in more detail
  • Playwright crawler (obeys robots.txt): a scripted browser that follows every same-site link breadth-first, up to 60 pages, and skips disallowed paths.
  • Playwright crawler (ignores robots.txt): the same crawler without the robots.txt check.
  • Crawl4AI + llama3.2: a crawler that ranks links with a keyword scorer and fetches pages best-first, up to 30 pages and link depth 4. The small local model extracts what matches the task from each fetched page, as markdown or as raw HTML. It does not choose which pages are fetched.
  • Claude Sonnet 5.5 (screenshots): the model sees screenshots of the page and acts with the mouse and keyboard.
  • Claude Sonnet 5.5 (page text): the model reads page text and uses tools to open links, open an address, or go back.
  • Scripted human baseline: a synthetic visitor with human-like browsing, used to estimate false positives.

Limits

  • Detection was at the ceiling, so the designs could not be ranked.
  • No classical hidden-link honeypot was tested, so no improvement over classical designs is shown.
  • Small samples (5 to 10 runs per cell), one website, one task, two models.
  • The human baseline is synthetic, not real visitors.
  • Crawl4AI's depth in the chain is capped by its crawl settings (at most pages 1 to 3 of 14 can be reached), so it cannot be compared with the other agents on depth.
  • Language-model replies were hand-coded by a single coder.
